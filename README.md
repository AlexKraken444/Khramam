# Храммам

Ироничный сайт вымышленной религии на Next.js App Router, React и TypeScript. Багряная палитра, адаптивная верстка, CSS-анимации, поддержка reduced motion и интерактивный ритуал. Фотография находится в `public/vasilissa.jpg`.

## Локальный запуск

```sh
npm ci
npm run dev
```

Открыть http://localhost:3000.

## Проверка

```sh
npm run typecheck
npm run build
node --experimental-strip-types --test tests/*.test.mjs
```

## Vercel

Импортировать репозиторий `AlexKraken444/Khramam` в Vercel. Framework Preset: Next.js, Root Directory: корень репозитория. Команда сборки: `npm run build`. Использовать Node.js 24.x (или совместимую с Next.js версию).

Для общего счётчика подключить **Upstash Redis** к проекту через Vercel Storage / Marketplace. Нужны серверные переменные `KV_REST_API_URL` и `KV_REST_API_TOKEN` (обычно добавляются интеграцией). Также поддерживаются `UPSTASH_REDIS_REST_URL` и `UPSTASH_REDIS_REST_TOKEN`. Не добавлять префикс NEXT_PUBLIC и не коммитить токены. После подключения сделать Redeploy. Для локальной работы скопировать `.env.example` в `.env.local` и заполнить значения отдельной тестовой базы.

Шрифты Cormorant Garamond и Manrope загружаются из Google Fonts в браузере; при отсутствии доступа используются Georgia и Arial. Во время сборки загрузка шрифтов не требуется.

Сайт — рофл. Религия вымышленная.

Счётчик благословений **общий для всех посетителей**, хранится в Redis и обновляется в видимых вкладках каждые 15 секунд и при возврате на страницу. POST `/api/blessings` атомарно проверяет дневное получение и увеличивает итог через Lua EVAL; повторный запрос возвращает текущий итог без увеличения. GET возвращает итог и статус посетителя, ответы не кешируются. Одно благословение за календарный день по Москве (UTC+3), время определяет сервер.

Посетитель определяется случайным идентификатором в HttpOnly cookie. Это ограничение на браузер, а не подтверждённого человека: очистка cookie или другой браузер позволяет получить благословение заново. Общий итог при этом не сбрасывается. Для строгого ограничения на человека нужна авторизация. При отсутствии базы или ошибках сайт показывает недоступность счётчика и не имитирует успешное получение. Старые локальные счётчики не импортируются в общий итог, поскольку их значения нельзя проверить.

Тесты проверяют протокол хранилища на подменённом REST-ответе, повторные запросы и границу суток; интеграцию с настоящей базой нужно проверить после её подключения.
